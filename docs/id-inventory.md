# Identifier inventory

This inventory treats an identifier as a semantic concept, not every local
variable ending in `Id`. One same-model subagent investigated each of the 25
semantic concepts below; a 26th focused audit checked session-related variants.
They read the implementation and existing tests; none modified the working tree.

### Scope and method

The source search covered `src/**/*.ts`, `src/**/*.mjs`, and `src/**/*.mts`, with
`package.json` checked first. Textual occurrences were deduplicated into semantic
identities; local map keys, collection names such as `completionIds`, and helper
predicates were grouped under the identity they carry rather than listed as new
IDs. Tests named in the table were inspected by the investigating subagents.

## Conclusion

The count looks high because the same value crosses several boundaries under
names such as `id`, `sourceId`, `completionId`, and `workflowId`. The
investigation found only a small number of likely naming/representation
consolidations:

- document the interactive child ID as one canonical value despite its
  `id`/`childId`/`agentId`/`sourceId` boundary names;
- document `JobState.id`/`jobId` and workflow `id`/`workflowId` as internal vs
  public aliases;
- document `completionGroupId`/`groupId`, wake-ID fields, and telemetry-ID
  fields as serialization aliases;
- consider derived or duplicated persisted fields only as a separate migration
  project (for example file-level parent-session metadata and `rootHash`).

The evidence does **not** support deleting the core IDs. `jobId`, `workflowId`,
child ID, `parentSessionId`, scope generation, `turnId`, `eventId`,
`deliveryId`, completion identity, pane identity, and backend scope solve
different lookup, ownership, deduplication, persistence, or transport
problems. Merging them would trade visible naming complexity for correctness
regressions.

## Reorganization phase 1

The first staged change adds `src/identifier-types.ts`, a branded taxonomy for
core string and numeric domains. It brands generated `InteractiveSubagentId`,
`InProcessJobId`, `WorkflowId`, `WorkflowAttemptId`, `EventId`, `DeliveryId`,
`WakeId`, `TelemetryCorrelationId`, `ProjectId`, `ConfirmationToken`, and
`HerdrRequestId` values without changing runtime formats or persisted/tool-facing
field names. The aliases are re-exported from `src/subagent.ts`; JSON, CLI, and
SDK boundaries remain plain strings.

The compile-time proof is in `tests/identifier-types.test.ts`; the existing
unrelated multiplexer working-tree changes were left untouched.
